## 2. 回顾与调试

### 2.1 KeytKan模式问题
- **问题描述**：上一节课使用KeytKan的0模式（单次模式）时，按键按下后状态会被立即清零，导致Debug时无法观察到持续的电平变化。
- **解决方案**：将KeytKan模式设置为1（支持连按模式），这样按下时状态置1，松手后状态归零，便于调试观察。

### 2.2 调试技巧
- **观察变量**：
  - 在Debug模式下，需要将变量（如KST）定义为全局变量（`Private a private -> Revibals -> KST`）。
  - 在Watch窗口（2WG）中，默认是16进制显示。右键点击变量，取消勾选 `X Display` 即可切换为十进制显示，更方便观察。
- **调试心得**：代码逻辑小细节容易出错，导致程序运行不正常，Debug是定位问题的关键手段。

## 3. 中断基本概念

### 3.1 处理器与外部设备通信方式
1.  **直接传输**：发出信号后不再关心，用于控制LED等简单场景。
2.  **查询式**：传输前检查对方状态，准备好才传输，否则停止或延迟。
3.  **中断式**：通过申请中断通知CPU，无论CPU在做什么，都会暂停当前任务去处理中断请求。
4.  **DMA（直接存储器访问）式**：实现外设与内存或内存与内存间的高速传输，无需CPU参与，效率最高。

### 3.2 中断的优势与全过程
- **优势**：
  - 解决CPU与外部设备速度不匹配问题。
  - 提高CPU效率，分时处理多任务。
  - 能实时响应外部事件，处理突发状况。
  - 具有高可靠性。
- **中断处理全过程**：
  1.  **中断发生**：CPU正在执行主程序时，突发一个事件请求CPU立即处理。
  2.  **中断响应**：暂停当前主程序，保存断点（当前执行位置），跳转到中断服务函数。
  3.  **中断处理**：执行中断服务函数中的任务。
  4.  **中断返回**：执行完中断服务函数后，返回断点处，继续执行主程序。

### 3.3 中断优先级与嵌套
- **优先级**：中断有优先级之分，高优先级的中断可以打断正在执行的低优先级中断。
- **嵌套**：高优先级中断打断低优先级中断，处理完后返回低优先级中断，再返回主程序，称为中断嵌套。
- **示例**：顾客进门（低优先级）与火灾发生（高优先级）。当两事件同时发生时，先处理火灾；若在处理火灾时来了顾客，则继续处理火灾，不响应顾客。

## 4. STM32中断系统

### 4.1 抢占优先级与子优先级
- **两种优先级**：
  - **抢占优先级**：用于中断嵌套，数值越小，优先级越高。可设置范围 0~15。
  - **子优先级**：当抢占优先级相同时，用于判断哪个中断先执行。可设置范围 0~15。
- **CubeMX默认设置**：
  - 在NVIC设置中，通常将4位全部分配给抢占优先级（`4 Bit for Pre-emption Priority`），因此子优先级无法设置，默认为0。

### 4.2 NVIC中断表与默认设置
- **中断表**：在 `System Core -> NVIC` 中可以看到中断表，已有中断（标记为0或15）已固定。
  - 例如：`Hard Fault Interrupt`（硬件错误中断），优先级为0，最高。
  - 例如：`TimeBase`（系统滴答定时器中断），优先级为15，最低。
- **中断使能**：用户需要在该表中为自己使用的中断打勾（Enable），并设置合适的优先级（不推荐设为0，建议中等值如8）。

## 5. 外部中断（EXTI）配置

### 5.1 硬件电路与电平变化
- **所有IO口**均可作为外部中断输入。
- **按键示例**：按键不按时，IO口为高电平；按下时，连到GND，变为低电平。
- **触发方式**：
  - **上升沿**：从低电平跳变到高电平，通常在松手时触发。
  - **下降沿**：从高电平跳变到低电平，通常在按下时触发。
  - **上升沿或下降沿**：按下和松手时都触发，共两次。

*Screenshot-[21:30] *Screenshot-[21:45]* *(例如：关于上升沿和下降沿的波形图)*

### 5.2 在CubeMX中配置GPIO与NVIC
1.  **配置GPIO功能**：
    - 将引脚模式从 `GPIO_Input` 改为 `GPIO_EXTI[编号]`。一个编号（如0、1、2…）只能被一个引脚使用。例如，PC0和PA0都连接EXTI0，但只能选择其中一个。
    - 设置用户标签（User Label），如 `L_Center`。
2.  **配置NVIC**：
    - 在 `NVIC` 选项卡中，找到对应的中断线（如 `EXTI0`），勾选使能，并设置优先级（建议设为8）。
3.  **配置GPIO Settings**：
    - 设置触发方式：`Falling Edge`, `Rising Edge` 或 `Rising/Falling Edge`。
    - 设置上下拉：根据硬件电路，若按键按下为低电平，则需选择内部上拉，确保默认状态为高电平。

### 5.3 配置触发方式与上下拉
- **本例设置**：
  - 将 `L_Center` 和 `R_Center` 配置为 `GPIO_EXTI0` 和 `GPIO_EXTI2`。
  - 触发方式选择 `Falling Edge`（按下时触发）。
  - GPIO设置中选择 `Pull-up`（上拉）。
- **常见错误**：
  - 触发方式未配置或配置错误，会导致中断不触发或异常触发（如摸一下引脚就触发）。
  - 上下拉配置错误，会导致按键按下时电平变化不正确。

## 6. 教程笔记：实现外部中断控制数字增减

### 6.1 步骤1：硬件与初始化
1.  新建工程，复制 `BLED` 文件夹。
2.  在CubeMX中配置 `PC0` 和 `PC2` 为外部中断模式，并设置好触发方式和上拉。
3.  在代码中，将原扫描函数中关于5号按键（对应 `L_Center`）和10号按键（对应 `R_Center`）的轮询代码注释或删除掉，因为它们已由中断处理。

### 6.2 步骤2：编写中断回调函数
1.  **找到中断服务函数**：在 `it.c` 文件中，找到对应的 `EXTI0_IRQHandler` 和 `EXTI2_IRQHandler` 函数。
2.  **跟踪到回调函数**：进入函数后，看到 `HAL_GPIO_EXTI_IRQHandler(GPIO_Pin)`，清除中断标志位后，调用 `HAL_GPIO_EXTI_Callback(GPIO_Pin)`。
3.  **复制弱定义函数**：找到 `__weak HAL_GPIO_EXTI_Callback()` 函数（通常在 `stm32f4xx_hal_gpio.c` 中），将此函数原型复制到用户代码区（如 `main.c` 的 `USER CODE BEGIN 4` 部分）。
    *Screenshot-[31:30] *(例如：如何找到并复制__weak函数)*
4.  **编写回调逻辑**：
    - 在回调函数中，必须**判断中断源**（`GPIO_Pin`）。
    ```c
    void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
    {
        if(GPIO_Pin == L_Center_Pin)
        {
            // 处理左边按键（如：Number++）
        }
        else if(GPIO_Pin == R_Center_Pin)
        {
            // 处理右边按键（如：Number--）
        }
    }
    ```
    - **重要**：不要在回调函数中直接写复杂的业务逻辑或长延时（如 `HAL_Delay`），这会阻塞其他中断。

### 6.3 步骤3：使用标志位处理（推荐方法）
- **原理**：将复杂任务放到主循环中处理，中断回调中只设置一个标志位。
1.  **定义全局标志变量**：
    ```c
    volatile uint8_t L_Center_Flag = 0;
    volatile uint8_t R_Center_Flag = 0;
    ```
    - 使用 `volatile` 防止编译器优化。
2.  **在回调函数中设置标志**：
    ```c
    if(GPIO_Pin == L_Center_Pin)
    {
        L_Center_Flag = 1;
    }
    ```
3.  **在主循环中处理**：
    ```c
    if(L_Center_Flag == 1)
    {
        L_Center_Flag = 0; // 先清标志
        // 执行复杂任务，如：Number++，并更新OLED显示
        Number++;
        OLED_ShowNum(0, 0, Number, 3, 16);
    }
    ```
    - **关键**：进入`if`后，**必须先清空标志位**，再执行任务。否则，任务将无限重复执行。

*Screenshot-[56:50] *(例如：演示未清除标志位导致程序逻辑错误的场景)*

### 6.4 步骤4：主循环处理
- 在主循环 `while(1)` 中，持续检查标志位。
- 这样，CPU大部分时间执行主循环，外部中断只快速记录事件，保证了系统实时性，也使任务逻辑更清晰。

### 6.5 关键点与结论
- **回调函数名称**：**必须复制**，不能手敲，防止写错。
- **中断来源判断**：必须判断，避免不同中断源混淆。
- **中断内函数**：保持简洁，避免长延时和复杂计算。
- **标志位用法**：标志位设置后，必须在主循环中**清空**，防止逻辑错误。
- **层级关系**：代码书写注意缩进，便于查找括号不匹配等错误。
- **Debug技巧**：如果程序编译后出现很多错误（如12个错误），优先检查第一个错误（最上方），通常是由于上一个函数没有正确闭合（丢失花括号）导致。

## 7. AI总结

本次课程系统讲解了STM32中的**外部中断**机制。

首先，我们回顾了上一节课 KeytKan 单次模式导致的调试问题并给出解决方案，强调了Debug在发现逻辑错误中的重要性。

核心知识包括：
1.  **中断原理**：中断是一种提高CPU效率、实时响应外部事件的机制。STM32支持中断嵌套，高优先级可打断低优先级。
2.  **优先级设置**：通过抢占优先级实现嵌套。在CubeMX默认设置中，子优先级被合并，无法独立设置。
3.  **外部中断（EXTI）配置**：所有IO口均可作为外部中断源，但相同编号的引脚互斥。配置时需在CubeMX中设置GPIO模式、NVIC使能、触发方式（Falling/Rising Edge）和内部上下拉。

教程演示了如何利用外部中断实现按键控制数字显示：
- 关键实践是使用**标志位模式**。中断回调函数只负责快速记录事件（置标志位 1），而耗时的工作（如显示、运算）则放到主循环中处理。这避免了中断处理时间过长导致系统卡死。
- **一个重要结训**是：使用标志位时，必须在同一轮判断中**先清标志再执行任务**，否则程序逻辑会进入死循环。
- 此外，编写中断回调函数时，函数名务必从固件库中复制，不能手动输入，并要正确判断中断源。

本次内容将学到的轮询扫描升级到了更高效、更实时的中断处理方式，是嵌入式开发中非常核心的技能。
