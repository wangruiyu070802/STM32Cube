# 课程概述

本节课主要讲解如何在 STM32 学习板上使用 CI24R1 2.4G 无线通信芯片。该芯片集成度高，仅需少量外围元件即可实现短距离无线通信，理论传输距离可达几十到100米（实测约20米）。课程设计了两个工程：**TX（发送端）**和 **RX（接收端）**，用于控制后续项目中的“蝴蝶”舵机动作。

> 注意：当前版本仅实现单向通信（TX→RX），因双向通信存在卡死问题尚未解决。

# 硬件介绍

## CI24R1 芯片与天线

- 板载左上角黑色芯片为 **CI24R1**，蛇形走线为天线。
- 原理图显示其引脚极少，仅需几个外围元件即可工作。

## 外围电路

- 主芯片 + 晶振 + 两个起振电容 + 滤波电容 + 零欧电阻 + 天线（RF接口）。
- 结构简单，适合板载集成。

# 软件准备工作

## 工程文件结构

需将以下6个文件复制到 `Drivers/User` 目录：

- `CI24R1.c` / `CI24R1.h`：芯片库函数
- `CI24R1_SPI.c` / `CI24R1_SPI.h`：SPI 接口文件（软件模拟）
- `simple_communication.c` / `simple_communication.h`：简易通信协议

在工程中仅需添加 `.c` 文件（`.h` 文件自动包含）。

## 引脚配置（软件SPI）

- 使用软件模拟 SPI，而非硬件 SPI（因为 CI24R1 为半双工，且硬件 SPI 配置存在未解决问题）。
- 引脚分配：
  - **CSN** (片选) → PB12
  - **SCK** (时钟) → PB13
  - **DATA** (数据) → PB15
- 配置函数：`APP_Config_SPI()`，内部使用标准库风格（实际改用 HAL 库实现）。
- 如需更换引脚，必须同时修改以下两处：
  1. `CI24R1_SPI.c` 中的 `GPIO_PIN_x`、`GPIOx` 以及 `DATA_OUT`/`DATA_IN` 函数
  2. `CI24R1.h` 中的引脚宏定义（`CSN_Pin`、`SCK_Pin`、`MSI_Pin`）

# CI24R1 库文件详解

## 地址配置（ADDR_BYTES）

- 地址长度为 4 字节，默认值 `0x88, 0x88, 0x88, 0x88`。
- 作用：类似“名字”，只有地址匹配的接收端才会处理该数据包。
- 建议：实际使用时修改为唯一地址，避免多组设备互相干扰。

## 工作频率（CHANNEL_FREQUENCY）

- 可在 2.4G 附近选择不同频道，默认为 **2440 MHz**（即 2.44 GHz）。
- 示例范围：`2400, 2401, ..., 2525`（具体值需参考数据手册）。
- **必须确保收发双方频率一致**，否则无法通信。

## 数据包长度与协议

- 固定长度为 **11 字节**（由宏 `PRELOAD_WIDTH` 定义，不建议修改）。
- 当前实际只使用了前 3 字节，后续 7 字节填充 0x00，最后一字节为校验和。
- 简易协议定义：
  - 帧头（1 字节）：`0xAA`
  - 控制指令（1 字节）：`0x01`（Prepare）、`0x02`（Fly）、`0x03`（左转）、`0x04`（右转）、`0x05`（Stop）、`0x06`（PowerOff）
  - 校验和（1 字节）：对帧头+指令求和后取反
- 校验函数：`Check_Pack()` 验证帧头与校验和，返回有效指令或 0（无效）。

# 发送端（TX）程序解析

## 初始化流程

```c
APP_Config_SPI();          // 配置软件SPI引脚
CI24R1_Init();             // 初始化CI24R1芯片
Check_CI24R1();            // 检查芯片是否存在（读写测试）
TX_Mode();                 // 设置为发送模式
```

- `Check_CI24R1()` 会阻塞等待直到芯片就绪（若失败则进入死循环）。

## 按键控制与指令封装

- 使用按键扫描，根据按键不同将指令写入 `TX_Buffer[1]`。
- `TX_Buffer[0]` = 帧头 `0xAA`
- `TX_Buffer[1]` = 控制指令（如 `COMMAND_PREPARE`）
- `TX_Buffer[2]` = 对 TX_Buffer[0] + TX_Buffer[1] 求和取反
- 其余字节（3~9）填充 0x00，第 10 字节为全包校验（暂未使用）。

## 发送函数

```c
if (TX_Package(TX_Buffer, PRELOAD_WIDTH) == TX_OK) {
    // 发送成功，待机
    HAL_Delay(10);
}
```

# 接收端（RX）程序解析

## 初始化流程

与发送端基本相同，唯最后一步改为 `RX_Mode()`。

## 接收与校验

```c
if (RX_Package(RX_Buffer) == RX_OK) {   // 返回0表示接收成功
    uint8_t cmd = Check_Pack(RX_Buffer); // 校验帧头+校验和，返回指令
    if (cmd != 0) {
        // 显示指令编号或对应字符串
        // 后续可根据指令控制舵机
    }
}
```

- `RX_Package()` 从芯片内部寄存器读取数据存入 `RX_Buffer`。
- `Check_Pack()` 验证帧头(0xAA)和校验和，返回指令字节（如 0x01~0x06）。

## 数据显示与控制

- 使用 `Show_Number()` 显示指令编号。
- 使用字符串显示对应动作（如 "Prepare"、"Fly " 等，注意空格清除残留字符）。
- 实际控制舵机动作将在后续课程实现。

# 使用注意事项

1. **收发双方一致性**
   - 频率（`CHANNEL_FREQUENCY`）必须相同
   - 地址（`ADDR_BYTES`）必须相同
   - 通信协议（帧头、校验方式）必须相同

2. **地址与频率唯一性**
   - 多人同时实验时，建议每组修改地址和频道，避免互相干扰。
   - 例如：将地址改为 `0x11,0x22,0x33,0x44`，频率改为 2445 MHz。

3. **引脚修改方法**
   - 若需更换IO口，需同步修改：
     - `CI24R1_SPI.c` 中的 `GPIO_PIN_x`、`GPIOx`
     - `CI24R1_SPI.c` 中的 `DATA_OUT`/`DATA_IN` 函数（涉及 GPIO 端口和引脚号）
     - `CI24R1.h` 中的引脚宏定义（`CSN_Pin`、`SCK_Pin`、`MSI_Pin`）

4. **数据包长度固定**
   - 不建议修改 `PRELOAD_WIDTH`，否则可能引发未定义问题。

# AI 总结

本节课系统讲解了 STM32 与 CI24R1 芯片进行 2.4G 无线通信的实现方法。重点包括：

1. 使用**软件模拟 SPI** 方式驱动 CI24R1，避免硬件 SPI 的半双工兼容问题。
2. 掌握芯片的**地址配置**和**工作频率配置**，确保收发双方参数完全一致。
3. 学习了**简易数据帧协议**的设计（帧头+指令+校验和），并实现发送和接收流程。
4. 通过按键控制发送端代码，将不同指令封装后发送；接收端通过校验和解包，提取有效指令用于显示或后续舵机控制。
5. 强调了实际应用中**地址和频道的唯一性**，防止多组设备互相干扰。

通过本课程，学生可以独立完成基于 CI24R1 的无线遥控器与接收器的基础开发，为后续控制机械蝴蝶项目打下基础。
